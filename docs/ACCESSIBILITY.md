# アクセシビリティ

最終更新：2026-11-07

## 優先事項と目標

FIDIM は、それ自体がアクセシビリティのための道具です。Windows では、`system-ui` や Yu Gothic などを指定したウェブページの本文が、UI用のフォントや細いフォントで表示され、長い文章がとても読みにくくなります。FIDIM は、こうしたフォントを読みやすい代替フォントに置き換えます。「すべてのフォント」を置き換えるモードを使えば、ディスレクシアの方など、どのウェブページも自分が最も読みやすいフォントで読みたい方にも役立ちます。

この文書が対象とするのは、次の2つです。

- 拡張機能そのもののUI（ポップアップと設定画面）
- FIDIM がウェブページの表示に与える影響

UIは WCAG 2.2 のレベル AA を目標とし、これを上限ではなく下限と考えています。AAより厳しい独自の基準もあります（[貢献者への期待](#貢献者への期待)を参照）。第三者による試験は受けていないため、これは目標であり、適合を表明するものではありません。

## ウェブページでの動作

FIDIM がウェブページに対して変更するのは、文字の書体と太さだけです。文字の大きさ、色、行間などには触れません。

- 日本語の本文が実際に表示されるフォントが置換対象のときだけ、`font-family` を置き換え先のフォント（初期値は `sans-serif`）にします。フォールバックに置換対象のフォントが書かれているだけなら、置き換えません
- 「すべてのフォント」モードでは、ページ内のすべての要素の `font-family` を置き換えます
- `font-weight` が 400 未満に指定されている要素は、`normal` にします。代替フォントで表示したときに、文字が薄くて読めなくなるのを防ぐためです。これは標準の動作で、設定で止めることはできません
- FIDIM を無効にしたとき、またはサイトを除外・除外解除したときは、ページを再読み込みして表示を切り替えます

## 対応している環境

- ブラウザ：Google Chrome（デスクトップ版）、Microsoft Edge で動作を確認済み
- OS：Windows で動作を確認済み。macOS など、ほかの OS ではまだ試していません
- スクリーンリーダー：Windows の NVDA で読み上げを確認済み。PC-Talker、macOS の VoiceOver など、ほかのスクリーンリーダーではまだ試していません
- すべての機能を、キーボードだけで操作できます

## 既知の制限

- **FIDIM を無効にしたときや、サイトを除外・除外解除したときに、ページが再読み込みされます。** フォームに入力している途中の内容は、失われることがあります。
  - 回避策：入力内容を送信・保存してから切り替えてください。
- **フォントを置き換えたことで、レイアウトが崩れるウェブページがあります。** 「すべてのフォント」モードでは、アイコンフォントで表示されているアイコンが、文字や記号に置き換わってしまうこともあります。
  - 回避策：設定画面の「除外リスト」に、そのサイトのドメインを登録してください。ポップアップの「このサイトを除外」からも登録できます。
- **Shadow DOM の中の文字は置き換えません。** Web Components を使ったウェブページでは、一部の文字が元のフォントのまま表示されることがあります。
- **ブラウザの設定画面、Chrome ウェブストア、ほかの拡張機能の画面（サイドパネルなど）では動作しません。** ブラウザの仕様で、拡張機能がこれらの画面に手を加えることができないためです。
- **設定画面で「すべてのフォント」を選んでいる間は、「個別に選択」の項目が操作できない状態になります。** この間、それらの項目には Tab キーで移動できません。
- **設定画面の「保存しました」「デフォルトに戻しました」の表示は、2秒で消えます。**

## アクセシビリティの問題を報告する

問題は [GitHub Issues](https://github.com/securecat/fidim/issues) で報告してください。日本語でも英語でも構いません。

次のことを書いてもらえると助かりますが、どれも任意です。

- 何をしようとしていたか（例：「このサイトの文字が置き換わらない」）
- 使っていた画面や機能。ウェブページの表示に関することなら、そのページのURL
- 何が起きたか、どうなると思っていたか
- OS、ブラウザのバージョン、FIDIM のバージョン
- 使っている支援技術（スクリーンリーダーなど）

障害の有無や内容を書く必要はありません。スクリーンショットや録画も必須ではありません。

## 対応の流れ

FIDIM は個人で開発しているため、返信や修正の期限はお約束できません。それでも、できるかぎり早く対応します。

- 報告を確認したら、Issue で返信します
- 回避策があれば、お知らせします
- 修正をリリースする前に、問題が解消したかどうかの確認をお願いすることがあります
- 修正の内容は [CHANGELOG.md](../CHANGELOG.md) に記載します

## 貢献者への期待

ここに挙げることは、人間の貢献者にもコーディングエージェントにも、同じように求めます。

UIを変更するときは、次を守ってください。

- フォームにはネイティブの要素（`<input>`・`<select>`・`<textarea>`）を使う。`<div>` や `<span>` をボタンの代わりにしない。画面内の操作には `<button>`、ページの移動には `<a>` を使う
- `disabled` 属性を使わない
- フォーカスインジケーターを消さない（`outline: none` を使わない）
- リンクの下線を消さない
- テキストのコントラスト比は、本文で 7:1 以上、補足的なテキストで 4.5:1 以上にする。ライトテーマとダークテーマのそれぞれで満たす
- 境界線やアイコンなど、テキスト以外の要素も、隣り合う色に対して 3:1 以上にする
- コントラストが必要な要素に `opacity` を使わない
- 文字サイズは、日本語で 16px 以上、英語で 14px 以上にする
- `font-family` は `sans-serif` にする（`system-ui` は使わない）
- ステータスメッセージを自動で消さない
- 自動スクロールなど、ひとりでに動くものを作らない

変更したあとは、キーボードだけですべて操作できること、NVDA などのスクリーンリーダーで内容が正しく読み上げられることを確認してください。

`content.js` を変更するときは、日本語の本文が実際に表示されるフォントで置換を判定すること、文字を細くしないこと（`font-weight` を 400 未満にしない）を守ってください。なお、`docs/index.html` は置換の動作を確かめるための見本ページなので、置換対象のフォントや細いウェイトを意図的に指定しています。
